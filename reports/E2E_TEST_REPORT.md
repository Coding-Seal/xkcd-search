## 1. Описание выполненной работы

### 1.1 Объект тестирования

Системное тестирование проверяет готовый продукт по бизнес-требованиям в полностью рабочем окружении. Тестируются два компонента:

- **REST API** (`cmd/xkcd`, порт 8080) — реальный бинарник с реальной SQLite БД и настроенным пользователем
- **Веб-фронтенд** (`cmd/web`, порт 8090) — реальный веб-сервер, проксирующий запросы к API

### 1.2 Виды системных тестов

| Вид | Кол-во | Описание |
|-----|--------|----------|
| API-Chain E2E (Python + requests) | 2 | Многошаговые цепочки HTTP-запросов к реальному API-бинарнику |
| Browser E2E (Playwright) | 12 | Сценарии взаимодействия пользователя с веб-интерфейсом |
| **Итого** | **14** | |

### 1.3 Используемые инструменты

| Инструмент | Назначение |
|------------|------------|
| Python 3 + `requests` | HTTP-клиент для API-chain тестов |
| Playwright (sync API) + pytest | Браузерное E2E-тестирование веб-фронтенда |
| `chromium` | Браузер для Playwright |
| GitHub Actions | Сервер непрерывной интеграции |
| `make e2e` | Запуск API-chain тестов (сборка + старт бинарника + тесты + остановка) |
| `make e2e-playwright` | Установка зависимостей + запуск Playwright тестов |

### 1.4 Тестовое окружение

**API-Chain:** реальный бинарник `build/xkcd` запускается на случайном порту через `make e2e`. БД предварительно заполняется командой `/api/update`. API_BASE_URL = `http://localhost:{PORT}`.

**Browser E2E:** веб-сервер `build/web-server` запущен на порту 8090, проксирует к API. `BASE_URL = http://localhost:8090`. Пользователь `bob/bob` должен существовать в БД.

### 1.5 Классификация тестов

#### По уровню изоляции

Системные (E2E) тесты обеспечивают **минимальную изоляцию** — проверяется готовый продукт в условиях, максимально приближённых к production:

| Компонент | API-Chain тесты | Browser E2E тесты |
|-----------|-----------------|-------------------|
| **БД** | Реальная SQLite | Реальная SQLite |
| **REST API** | Реальный бинарник | Реальный бинарник (через прокси) |
| **Веб-сервер** | Не используется | Реальный бинарник |
| **XKCD API** | Реальный (xkcd.com) | Реальный |
| **Браузер** | — | Chromium (Playwright) |

#### По подходу к тестированию

| Подход | Описание | Применение |
|--------|----------|------------|
| **Чёрный ящик (black-box)** | Тестировщик взаимодействует с системой только через публичный интерфейс | API-Chain: HTTP-запросы к реальному API; Browser: действия пользователя в браузере (клики, заполнение форм) |

### 1.6 Непрерывная интеграция

```
make build → make e2e (API-chain) → make e2e-playwright (Browser)
```

API-chain тесты в `make e2e`: сборка бинарника → запуск на фоне → `sleep 10s` → Python-скрипты → kill. Playwright тесты: установка зависимостей → `playwright install chromium` → `pytest test/e2e/playwright/ -v`.

### 2.3 Описание сценариев

**Сценарий 1: Получение JWT и запуск обновления индекса**
- Предусловия: бинарник `build/xkcd` запущен, пользователь `bob/bob` с правами admin существует в БД
- Шаги: `POST /api/login {"login":"bob","password":"bob"}` → извлечь токен из заголовка `Authorization` → `POST /api/update` с заголовком `Authorization: <token>` → 200
- Ожидаемый результат: оба запроса возвращают HTTP 200, индекс обновлён

**Сценарий 2: Поиск комикса и получение по ID (3-шаговая цепочка)**
- Предусловия: индекс заполнен (после сценария 1), запрос `apple,doctor` должен находить комикс с `img = "https://imgs.xkcd.com/comics/an_apple_a_day.png"`
- Шаги: `POST /api/login` → JWT; `GET /api/pics?search=apple,doctor` → проверить наличие ожидаемого URL в результатах; `GET /api/comic/{id}` с ID первого результата → проверить совпадение `id`
- Ожидаемый результат: поиск находит ожидаемый комикс, `/api/comic/{id}` возвращает тот же ID

**Сценарий 3: Анонимный пользователь видит форму поиска**
- Предусловия: веб-сервер запущен
- Шаги: открыть `BASE_URL/` → проверить непустой заголовок страницы → проверить наличие `<form>` → проверить видимость `<input type="text">`
- Ожидаемый результат: форма и поле ввода видимы

**Сценарий 4: Анонимный поиск**
- Предусловия: нет
- Шаги: открыть `/` → ввести `"apple"` → нажать Enter → дождаться загрузки
- Ожидаемый результат: есть элементы `img`/`.comic`/`article` ИЛИ сообщение об отсутствии результатов

**Сценарий 5: Пустой поиск не вызывает 5xx**
- Предусловия: нет
- Шаги: открыть `/` → программно отправить пустую форму → дождаться загрузки
- Ожидаемый результат: URL не None, заголовок страницы не содержит `"error"`, статус < 500

**Сценарий 6: Страница /login отображает поля формы**
- Предусловия: нет
- Шаги: открыть `/login` → проверить видимость `<form>`, поля логина и поля пароля
- Ожидаемый результат: оба поля видимы

**Сценарий 7: Неверные учётные данные**
- Предусловия: нет
- Шаги: открыть `/login` → ввести `"no_such_user_xyzzy"/"wrong_password_xyzzy"` → нажать Enter → ждать загрузки
- Ожидаемый результат: URL содержит `/login` ИЛИ страница содержит слово `"error"`/`"invalid"`/`"incorrect"`

**Сценарий 8: Успешный вход → редирект**
- Предусловия: пользователь `bob/bob` существует
- Шаги: открыть `/login` → ввести `"bob"/"bob"` → Enter → ждать загрузки
- Ожидаемый результат: URL не содержит `/login`

**Сценарий 9: Авторизованный пользователь видит кнопку избранного**
- Предусловия: пользователь залогинен
- Шаги: перейти на `/` → ввести `"apple"` → Enter → ждать → найти кнопку `button[class*='fav']` или `form[action*='fav'] button`
- Ожидаемый результат: кнопка избранного присутствует (если есть результаты)

**Сценарий 10: Страница /favorites без серверной ошибки**
- Предусловия: пользователь залогинен
- Шаги: открыть `BASE_URL/favorites`
- Ожидаемый результат: HTTP статус < 500, тело страницы не пустое

**Сценарий 11: Добавление в избранное**
- Предусловия: пользователь залогинен, есть результаты поиска
- Шаги: поиск `"apple"` → кликнуть первую кнопку избранного → перейти на `/favorites`
- Ожидаемый результат: на `/favorites` есть хотя бы один элемент ИЛИ сообщение о пустом состоянии

**Сценарий 12: Клик по navbar-ссылке**
- Предусловия: нет
- Шаги: открыть `/login` → найти `<a href="/">` или первую ссылку в `<nav>` → кликнуть → ждать загрузки
- Ожидаемый результат: URL равен `BASE_URL/` или `BASE_URL`

**Сценарий 13: Поисковый запрос отражён после submit**
- Предусловия: нет
- Шаги: открыть `/` → ввести `"linux"` → Enter → ждать
- Ожидаемый результат: `"linux"` присутствует в URL ИЛИ в значении поля input

**Сценарий 14: Анонимный доступ к /favorites**
- Предусловия: нет (не залогинен)
- Шаги: открыть `BASE_URL/favorites`
- Ожидаемый результат: HTTP статус < 500; URL содержит `/login` ИЛИ страница содержит `"login"` ИЛИ `"empty"` ИЛИ `"no favorites"` ИЛИ тело > 100 символов
