## 1. Описание выполненной работы

### 1.1 Объект тестирования

Системное тестирование проверяет готовый продукт по бизнес-требованиям в полностью рабочем окружении. Тестируются два компонента:

- **REST API** (`cmd/xkcd`, порт 8080) — реальный бинарник с реальной SQLite БД и настроенным пользователем
- **Веб-фронтенд** (`cmd/web`, порт 8090) — реальный веб-сервер, проксирующий запросы к API

### 1.2 Виды системных тестов

| Вид | Кол-во | Описание |
|-----|--------|----------|
| API-Chain E2E (Python + requests) | 3 | Многошаговые цепочки HTTP-запросов к реальному API-бинарнику |
| Browser E2E (Playwright) | 12 | Сценарии взаимодействия пользователя с веб-интерфейсом |
| **Итого** | **15** | |

### 1.3 Используемые инструменты

| Инструмент | Назначение |
|------------|------------|
| Python 3 + `requests` | HTTP-клиент для API-chain тестов |
| Playwright (sync API) + pytest | Браузерное E2E-тестирование веб-фронтенда |
| `chromium` | Браузер для Playwright |
| GitHub Actions | Сервер непрерывной интеграции |
| `make e2e` | Запуск API-chain тестов (сборка + старт бинарника + тесты + остановка) |
| `make e2e-playwright` | Установка зависимостей + запуск Playwright тестов |

### 1.4 Тестовое окружение

**API-Chain:** реальный бинарник `build/xkcd` запускается на случайном порту через `make e2e`. БД предварительно заполняется командой `/api/update`. `API_BASE_URL = http://localhost:{PORT}`.

**Browser E2E:** веб-сервер `build/web-server` запущен на порту 8090, проксирует к API. `BASE_URL = http://localhost:8090`. Пользователь `bob/bob` должен существовать в БД.

### 1.5 Классификация тестов

#### По уровню изоляции

Системные (E2E) тесты обеспечивают **минимальную изоляцию** — проверяется готовый продукт в условиях, максимально приближённых к production:

| Компонент | API-Chain тесты | Browser E2E тесты |
|-----------|-----------------|-------------------|
| **БД** | Реальная SQLite | Реальная SQLite |
| **REST API** | Реальный бинарник | Реальный бинарник (через прокси) |
| **Веб-сервер** | Не используется | Реальный бинарник |
| **XKCD API** | Реальный (xkcd.com) | Реальный |
| **Браузер** | — | Chromium (Playwright) |

#### По подходу к тестированию

| Подход | Описание | Применение |
|--------|----------|------------|
| **Чёрный ящик (black-box)** | Тестировщик взаимодействует с системой только через публичный интерфейс | API-Chain: HTTP-запросы к реальному API; Browser: действия пользователя в браузере (клики, заполнение форм) |

#### По назначению теста

| Назначение | API-Chain | Playwright | Итого |
|------------|-----------|------------|-------|
| Штатный сценарий (EC) | 2 | 8 | **10** |
| Путь ошибки (EP) | 1 | 3 | **4** |
| Граничный (BV) | 0 | 1 | **1** |
| **Итого** | **3** | **12** | **15** |

#### По объекту тестирования

| Категория | Файл | Тесты | Предусловия |
|-----------|------|-------|-------------|
| Обновление индекса (API) | `test/e2e/update.py` | 2 | Бинарник запущен; пользователь `bob/bob` с ролью admin существует |
| Поиск + комикс (API) | `test/e2e/pics.py` | 1 | Бинарник запущен; индекс заполнен; пользователь `bob/bob` существует |
| Авторизация (браузер) | `test/e2e/playwright/test_web.py` | 3 | Веб-сервер запущен; для позитивных — пользователь `bob/bob` в БД |
| Поиск (браузер) | `test/e2e/playwright/test_web.py` | 3 | Веб-сервер запущен; индекс заполнен |
| Избранное (браузер) | `test/e2e/playwright/test_web.py` | 4 | Веб-сервер запущен; пользователь `bob/bob` в БД; индекс заполнен |
| Навигация (браузер) | `test/e2e/playwright/test_web.py` | 2 | Веб-сервер запущен |

### 1.6 Непрерывная интеграция

```
make build → make e2e (API-chain) → make e2e-playwright (Browser)
```

API-chain тесты в `make e2e`: сборка бинарника → запуск на фоне → `sleep 10s` → Python-скрипты → kill. Playwright тесты: установка зависимостей → `playwright install chromium` → `pytest test/e2e/playwright/ -v`.

### 2.3 Описание сценариев

---

#### РАЗДЕЛ A. Обновление индекса (API)

---

**Сценарий 1: Администратор получает JWT и запускает обновление индекса**

- Предусловия: бинарник `build/xkcd` запущен; пользователь `bob/bob` с правами admin существует в БД
- Шаг 1: `POST /api/login {"login":"bob","password":"bob"}` — пользователь входит в систему
- Шаг 2: извлечь токен из заголовка `Authorization` ответа — получен JWT
- Шаг 3: `POST /api/update` с заголовком `Authorization: <token>` — запрос на обновление индекса
- Ожидаемый результат: оба запроса возвращают HTTP 200; индекс обновлён

---

**Сценарий 2: Попытка обновления индекса без токена авторизации**

- Предусловия: бинарник `build/xkcd` запущен; токен не получался
- Шаг 1: `POST /api/update` без заголовка `Authorization` — попытка вызвать защищённый endpoint
- Ожидаемый результат: HTTP 401 Unauthorized; индекс не изменился

---

#### РАЗДЕЛ B. Поиск и получение комикса (API)

---

**Сценарий 3: Пользователь ищет комиксы и получает один по ID**

- Предусловия: бинарник запущен; индекс заполнен; пользователь `bob/bob` существует; запрос `apple,doctor` возвращает комикс с `img = "https://imgs.xkcd.com/comics/an_apple_a_day.png"`
- Шаг 1: `POST /api/login {"login":"bob","password":"bob"}` — пользователь входит в систему, получает JWT
- Шаг 2: `GET /api/pics?search=apple,doctor` с токеном — пользователь выполняет поиск, проверяет наличие ожидаемого URL в результатах
- Шаг 3: `GET /api/comic/{id}` с ID первого результата — пользователь получает конкретный комикс по ID, проверяет совпадение поля `id`
- Ожидаемый результат: поиск находит ожидаемый комикс; `/api/comic/{id}` возвращает тот же ID

---

#### РАЗДЕЛ C. Авторизация (Browser)

---

**Сценарий 4: Успешный вход в систему → редирект на главную**

- Предусловия: веб-сервер запущен; пользователь `bob/bob` существует в БД; пользователь не авторизован
- Шаг 1: открыть `/login` — загружается форма входа
- Шаг 2: ввести логин `"bob"` в поле login
- Шаг 3: ввести пароль `"bob"` в поле password
- Шаг 4: нажать кнопку «Login» / Enter — отправить форму
- Шаг 5: дождаться загрузки страницы
- Ожидаемый результат: URL не содержит `/login`; пользователь перенаправлен на главную или другую страницу

---

**Сценарий 5: Вход с неверным паролем → остаётся на /login**

- Предусловия: веб-сервер запущен; пользователь не авторизован
- Шаг 1: открыть `/login`
- Шаг 2: ввести логин `"bob"`, пароль `"wrongpassword"`
- Шаг 3: нажать Enter — отправить форму
- Шаг 4: дождаться загрузки
- Ожидаемый результат: URL содержит `/login`; пользователь не перенаправлен

---

**Сценарий 6: Форма /login отображает оба поля и принимает ввод**

- Предусловия: веб-сервер запущен; пользователь не авторизован
- Шаг 1: открыть `/login`
- Шаг 2: проверить видимость поля логина и поля пароля
- Шаг 3: ввести текст в каждое поле — убедиться, что ввод принимается
- Ожидаемый результат: оба поля видимы; значения успешно введены

---

#### РАЗДЕЛ D. Поиск (Browser)

---

**Сценарий 7: Анонимный пользователь видит форму поиска на главной**

- Предусловия: веб-сервер запущен; пользователь не авторизован
- Шаг 1: открыть `/` — главная страница
- Шаг 2: проверить, что заголовок страницы не пустой
- Шаг 3: проверить наличие `<form>` и видимость текстового поля ввода
- Ожидаемый результат: форма и поле ввода видимы; страница загружается без ошибок

---

**Сценарий 8: Анонимный поиск по запросу возвращает результаты**

- Предусловия: веб-сервер запущен; индекс заполнен; пользователь не авторизован
- Шаг 1: открыть `/`
- Шаг 2: ввести `"apple"` в поле поиска
- Шаг 3: нажать Enter — отправить форму
- Шаг 4: дождаться загрузки результатов
- Ожидаемый результат: страница содержит элементы комиксов (`img`, `.comic-card`) ИЛИ сообщение об отсутствии результатов; нет 5xx ошибки

---

**Сценарий 9: Авторизованный пользователь видит кнопку избранного в результатах поиска**

- Предусловия: пользователь `bob/bob` существует в БД; индекс заполнен; веб-сервер запущен
- Шаг 1: открыть `/login`, ввести `bob/bob`, нажать Enter — войти в систему
- Шаг 2: перейти на `/`
- Шаг 3: ввести `"apple"` в поле поиска, нажать Enter
- Шаг 4: дождаться загрузки результатов
- Ожидаемый результат: среди результатов видна кнопка добавления в избранное (`.favorite-star`); анонимный пользователь её не видит

---

**Сценарий 10: Пустой поиск не вызывает серверную ошибку**

- Предусловия: веб-сервер запущен; пользователь не авторизован
- Шаг 1: открыть `/`
- Шаг 2: оставить поле поиска пустым, отправить форму программно
- Шаг 3: дождаться загрузки
- Ожидаемый результат: HTTP статус < 500; заголовок страницы не содержит `"error"`; страница загружается корректно

---

#### РАЗДЕЛ E. Избранное (Browser)

---

**Сценарий 11: Авторизованный пользователь открывает /favorites — список пуст**

- Предусловия: пользователь `bob/bob` существует в БД; избранное не заполнено; веб-сервер запущен
- Шаг 1: открыть `/login`, ввести `bob/bob`, нажать Enter — войти в систему
- Шаг 2: открыть `/favorites`
- Шаг 3: дождаться загрузки страницы
- Ожидаемый результат: страница загружается без 5xx; список комиксов пуст или отображается сообщение о пустом состоянии

---

**Сценарий 12: Пользователь добавляет комикс в избранное → видит его на /favorites**

- Предусловия: пользователь `bob/bob` существует в БД; индекс заполнен; избранное пустое; веб-сервер запущен
- Шаг 1: открыть `/login`, ввести `bob/bob`, нажать Enter — войти в систему
- Шаг 2: перейти на `/`, ввести `"apple"`, нажать Enter — выполнить поиск
- Шаг 3: дождаться результатов
- Шаг 4: кликнуть кнопку избранного (`.favorite-star`) у первого комикса
- Шаг 5: открыть `/favorites`
- Ожидаемый результат: на странице `/favorites` присутствует хотя бы один комикс

---

**Сценарий 13: Пользователь добавляет комикс в избранное, затем убирает его → список снова пустой**

- Предусловия: пользователь `bob/bob` существует в БД; индекс заполнен; веб-сервер запущен
- Шаг 1: открыть `/login`, ввести `bob/bob`, нажать Enter — войти в систему
- Шаг 2: перейти на `/`, ввести `"apple"`, нажать Enter — выполнить поиск
- Шаг 3: кликнуть кнопку избранного (`.favorite-star`) у первого комикса — добавить в избранное
- Шаг 4: открыть `/favorites` — убедиться, что комикс присутствует
- Шаг 5: кликнуть кнопку избранного у того же комикса ещё раз — удалить из избранного
- Шаг 6: открыть `/favorites`
- Ожидаемый результат: список избранного пуст

---

**Сценарий 14: Анонимный пользователь открывает /favorites — нет серверной ошибки**

- Предусловия: веб-сервер запущен; пользователь не авторизован (нет cookie Authorization)
- Шаг 1: открыть `/favorites` напрямую без предварительной авторизации
- Шаг 2: дождаться загрузки страницы
- Ожидаемый результат: HTTP статус < 500; страница содержит `/login` редирект ИЛИ пустое состояние ИЛИ тело страницы > 100 символов (не пустая страница)

---

#### РАЗДЕЛ F. Навигация (Browser)

---

**Сценарий 15: Клик по ссылке «Home» в навигации → переход на главную**

- Предусловия: веб-сервер запущен
- Шаг 1: открыть `/login` — любая не-главная страница
- Шаг 2: найти ссылку `<a href="/">Home</a>` в навигационном меню
- Шаг 3: кликнуть по ссылке
- Шаг 4: дождаться загрузки страницы
- Ожидаемый результат: URL равен `BASE_URL/` или `BASE_URL`; отображается форма поиска
